# VR 環境構築 議事録 (2026-06-15)

NixOS + Meta Quest 3 で VRChat を中心とした VR 環境を構築した際の作業記録。
やったこと・試したこと・判明した制約・最終構成をまとめる。

## 1. 前提: 動画再生と D3D11 クラッシュ (前日までに解決済み)

- **症状**: VRChat の AVPro 動画プレイヤーが動かない / `InitializeEngineGraphics failed`(D3D11 初期化失敗) でクラッシュ。
- **原因**: `nvidia.nix` の CUDA スタック有効化が引き金。DXVK 2.7.1 のバグ #5094（libcuda / CUDA interop 拡張 `VK_NVX_binary_import` との衝突）。
- **対処**: RTSP Proton 同梱の DXVK を **2.6.2 に差し替え**（dll をバックアップ後上書き）。デスクトップ起動・YouTube 再生ともに成功。
- メモ: [[vrchat-linux-video]] に手順記録済み。

## 2. WiVRn でのVR接続

### やったこと

- `services.wivrn` を導入（`autoStart` / `openFirewall` / `highPriority` / `steam.importOXRRuntimes`）。
- OpenComposite (`home/modules/apps/vr.nix`) で OpenVR→OpenXR 変換し SteamVR を回避。
- Quest 3 に Meta Store 版 WiVRn アプリをインストール。

### 試して却下したもの

- **Virtual Desktop**: PC 側 Streamer が Windows 専用で **Linux 非対応**。採用不可。
- **xrizer**(OpenComposite 代替): 現行 VRChat でグリップ操作の不具合 → OpenComposite を採用。
- `services.wivrn.defaultRuntime = true`: 新しい WiVRn では廃止 (assertion エラー) → 削除。

### トラブル: 「互換性のないサーバー」

- **症状**: Quest から接続すると「互換性のないサーバー」。
- **原因**: サーバー = WiVRn **26.2.3**（nixpkgs 26.05 同梱）、Quest = Meta Store 最新 **26.6**。WiVRn はサーバー/クライアントのバージョン系列一致が必須で、26.2 ⇄ 26.6 は非互換。
- **対処**: サーバーを 26.6 に更新。nixpkgs 未マージの **PR #531078 (wivrn: 26.2.3 → 26.6)** の `package.nix` を `nix-configs/pkgs/wivrn/` にローカル取り込みし、`services.wivrn.package` で差し替え。
  - src hash / monado hash / `patches/apply.sh` 適用まで `nix build` で検証済み。

### 重要な落とし穴: os-switch 後のユーザーサービス

- `os-switch` でシステムには 26.6 が入ったが、**稼働中サービスは 26.2.3 のまま**だった。
- 原因: **NixOS は systemd の "user" サービスを rebuild 時に自動再起動しない**。
- 対処:

  ```sh
  systemctl --user daemon-reload && systemctl --user restart wivrn
  ```

- → ログが `WiVRn 26.6 starting` になり接続成功。**今後 WiVRn を更新したら毎回この再起動 (or 再ログイン) が必要。**

## 3. 音声を Quest に流す

- WiVRn 接続中は仮想 PipeWire シンク `WiVRn` とソース `WiVRn(microphone)` が自動生成される。
- 既定出力を切り替え:

  ```sh
  wpctl set-default <WiVRnシンクID>   # 例: 158
  ```

- 注意点:
  - 既に起動中のアプリは旧出力に繋がったまま → 必要なら再起動 or ストリーム移動。
  - Quest 切断時はシンクが消えて既定が戻る。再接続後に再選択が必要。
  - マイクも Quest にするなら `WiVRn(microphone)` を既定入力に (音質はデスクのマイクが上)。

## 4. オーバーレイ (XSOverlay / OVR Toolkit / OyasumiVR)

### 結論: Windows製オーバーレイは原理的に使えない

| アプリ | 可否 | 理由 |
|---|---|---|
| XSOverlay | ✕ | Windows専用の OpenVR オーバーレイアプリ |
| OVR Toolkit | ✕ | 同上 |
| OVR Advanced Settings | ✕ | OSS だが OpenVR オーバーレイ。SteamVR 必須 |
| OyasumiVR | ✕ | Windows専用 + Windows API 依存。バッテリー取得も不可 |

- **核心**: OpenComposite は OpenVR の `IVROverlay`(オーバーレイAPI) を実装していない。ゲーム本体を OpenXR に変換するだけで、別プロセスのオーバーレイアプリを同居させる仕組みを持たない。SteamVR 非使用構成では Windows オーバーレイは重ねられない。

### 採用: Linux ネイティブの wayvr + motoc

- **wayvr** (旧 WlxOverlay-S, nixpkgs 26.05 に 26.2.1): XSOverlay にインスパイアされた OpenXR オーバーレイ。Monado/WiVRn のマルチアプリ合成機構に乗り、**VRChat と同時表示できる**。WiVRn では追加設定不要。
  - 機能: デスクトップ画面の VR 内表示 / 仮想キーボード / 手首ウォッチUI (時計・バッテリー)。
  - 起動: `wayvr --openxr`
- **motoc** (nixpkgs に 0.3.6): プレイスペース調整・フルボディトラッキング校正。OVR Advanced Settings の代替。
- 導入: `home/modules/apps/vr.nix` の `home.packages` に追加。
- wayvr に無い機能: デスクトップ通知転送・リッチなメディアウィジェット・凝ったテーマ (Linux ネイティブには現状なし)。

### その他の選択肢 (パラダイム違い)

- **StardustXR** (`stardust-xr-server` / `stardust-xr-flatland`, nixpkgs あり): VR 空間デスクトップ環境。より実験的。
- **WayVR Dashboard** (XSOverlay のパネル/ランチャーに近い GUI): **nixpkgs 未パッケージ**、自前 flake 化が必要。

## 5. 解像度・画質改善 (NVENC AV1)

### 問題

- 解像度が低い・眠い画質。
- 原因: 取り込んだ WiVRn ビルドが **CUDA 無効 = NVENC 無効**。WiVRn のエンコーダ既定は「NVIDIA かつ nvenc 付きビルド時のみ nvenc、それ以外 vaapi/x264」。NVIDIA で vaapi はまともに動かず、Vulkan エンコード/x264 にフォールバックしていた。
- RTX 4070 + Quest 3 は **NVENC AV1** に最適 (AV1 は同ビットレートで最も鮮明、Quest 3 は AV1 HW デコード対応)。

### 対処

- `services.wivrn.package` の callPackage に `cudaSupport = true` を渡し NVENC を有効化。
- `services.wivrn.config` でエンコーダを固定:

  ```nix
  config.json = {
    bit-depth = 10;
    encoder = { encoder = "nvenc"; codec = "av1"; };
  };
  ```

- 解像度スケール・ビットレートは **ヘッドセット側 (`wivrn-dashboard`)** で調整 (サーバー config では決められない)。AV1 なら 80〜120Mbps でかなり鮮明。

### 重要な落とし穴: dlopen と RUNPATH

- WiVRn の NVENC は `libnvidia-encode.so.1` / `libcuda.so.1` を **soname で dlopen** する。
- これらは NixOS では `/run/opengl-driver/lib` にしか無く、バイナリの RUNPATH が空だと実行時に解決できず NVENC が無効化される。
- `autoAddDriverRunpath` は **dlopen 対象を検出しない**（DT_NEEDED が無いため）。
- さらに `highPriority` の setcap 下では **`LD_LIBRARY_PATH` が無視される** (AT_SECURE)。
- 対処: `overrideAttrs` の `postFixup` で実体バイナリと .so の **RUNPATH に `/run/opengl-driver/lib` を絶対パスで追加** (絶対パスの RUNPATH は AT_SECURE でも有効)。
  - `readelf -d` で RUNPATH 反映、`strings` で `video_encoder_nvenc` / `NvEncodeAPICreateInstance` シンボルを確認済み。
- Vulkan は ICD の絶対パスで解決されるため動画自体は流れていた → **NVENC だけが解決できずフォールバックしていた**、というのが切り分けの肝。

## 6. VRCX 連携

### 結論

| 機能 | WiVRn+OpenComposite で |
|---|---|
| VRCX 本体 (フレンド/インスタンス/履歴管理) | ○ 動く (VR非依存、nixpkgsに `vrcx` 2026.05.03) |
| VRCX ネイティブ VR オーバーレイ | ✕ `IVROverlay` 依存のため不可 |
| VRCX 通知 → wayvr で VR 内表示 | ◎ **動く (正解ルート)** |

### 正解ルート: VRCX 通知 → wayvr (SteamVR不要)

- VRCX の `XSOverlay.cs` は通知を `127.0.0.1:42069`(UDP) へ JSON 送信するだけ (OpenVR 不使用)。
- wayvr の `notifications.rs` が **同じ 42069 を listen** し、VRCX と同一スキーマをパースして VR 内トースト表示 (コードに `// vrcx embeds icons as b64` と明記 = VRCX 互換を意図)。
- 手順:
  1. WiVRn セッション内で `wayvr --openxr`
  2. VRCX → Settings → VR/Notifications で **「XSOverlay Notifications」を ON**、通知種別を選択
  3. 同一マシン localhost で繋がる (ネット越し不可)。フレンドの参加/退出等が VR 内トーストで出る。
- 補足: `vrcx` は既に `home/packages/gaming.nix` に導入済みだった → 追加設定不要。

### 起動フロー

1. `just os-switch`
2. `systemctl --user daemon-reload && systemctl --user restart wivrn` (WiVRn 更新時は毎回)
3. Quest を WiVRn で接続
4. `wivrn-dashboard` で解像度スケール・ビットレートを調整
5. VRChat を VR 起動オプションで起動:

   ```
   WINEDLLOVERRIDES="iyuv_32=" PRESSURE_VESSEL_FILESYSTEMS_RW=/run/user/1000/wivrn/comp_ipc gamemoderun %command%
   ```

   (`--no-vr` は外す)
6. オーバーレイ: `wayvr --openxr` / プレイスペース調整: `motoc`
7. VRCX: 「XSOverlay Notifications」ON で通知を wayvr に表示

## 8. 学び・再ハマり防止メモ

- **WiVRn のサーバー/クライアントはバージョン系列一致が必須**。Store 版が先行するので nixpkgs 側を追従させる。
- **os-switch は systemd user サービスを再起動しない**。WiVRn 更新後は手動再起動 or 再ログイン。
- **Windows 製 OpenVR オーバーレイ (XSOverlay/OVR Toolkit/OyasumiVR/OVR Advanced Settings) は OpenComposite 構成で使えない**。Linux ネイティブの wayvr/motoc に置換。
- **NVENC は dlopen 方式**なので、NixOS では RUNPATH に `/run/opengl-driver/lib` を入れないと効かない。`autoAddDriverRunpath` も `LD_LIBRARY_PATH`(setcap時) も当てにできない。
- **VRCX のオーバーレイ連携は XSOverlay UDP 通知(42069)経由**。wayvr がそのまま受け皿になる。

### 将来のメンテ

- nixpkgs が WiVRn 26.6 を取り込んだら (PR #531078 マージ後)、`pkgs/wivrn/` とローカル override を削除して標準パッケージに戻せる。
- エンコード品質に不満が出たら `wivrn-dashboard` でビットレート調整 → それでも不足なら設定を見直す。
- 10bit で不具合が出たら `bit-depth` を 8 に下げる。
